2. CONCRETE CODE AND SECURITY IMPROVEMENTS

Smart Contract (Commit 6673b34, contracts/stellar_split_bill/src/lib.rs):
- Soroban SDK Modernization: Upgraded from Soroban SDK v20.0.0 to v29.0.0, targeting wasm32v1-none. This resolved Rust 1.97.1 compiler incompatibilities and ethnum dependency errors.
- Typed Contract Errors: Eliminated unhandled panics and implemented a typed 12-code contract error enum (Error): AlreadyInitialized, NotInitialized, BillNotFound, BillClosed, InvalidAmount, AmountExceedsRemaining, Unauthorized, InvalidState, ContractPaused, PayeeCannotBePayer, Overflow, and ReentrancyGuard.
- Cryptographic Authorization: Enforced require_auth across all state-mutating entrypoints (initialize, create_bill, pay_bill, remit, close_bill, emergency_stop, resume).
- Invariant Enforcement: Enforced that the payee cannot contribute to their own bill (Error::PayeeCannotBePayer), that payments must be strictly greater than zero, and that payments cannot exceed the remaining balance.
- Checked Arithmetic: Replaced standard math operators with checked_add trapping overflow via Error::Overflow.
- Storage TTL Bumping: Fixed storage mismatch by storing admin in instance storage (INSTANCE_TTL_LOW=10,000, INSTANCE_TTL_HIGH=20,000) and persistent bills with extend_ttl (PERSISTENT_TTL_LOW=20,000, PERSISTENT_TTL_HIGH=50,000) to protect records from ledger archiving.
- Typed Contract Events: Implemented typed events (BillCreatedEvent, BillPaidEvent, BillCompletedEvent, BillClosedEvent, RemitEvent) published via Soroban event macros without string symbol constraints.
- Reentrancy Guard: Implemented stateful ReentrancyLock guard across token transfer paths.

Backend Service (Commit 68da0ae, backend/app.js and backend/index.js):
- Modular Architecture: Separated Express application creation from network listener execution for unit testability.
- Security Headers and Rate Limiting: Integrated helmet, strict CORS, and express-rate-limit (100 requests / 15 minutes).
- Strict Bounds Validation: Validates that bill IDs are positive integers between 1 and 1,000,000, rejecting non-numeric, negative, floating-point, or out-of-range inputs with HTTP 400.
- Offline Simulation Fix: Replaced live server.getAccount calls on ephemeral read keypairs (which caused fatal 404 errors) with offline Account instances, enabling deterministic simulation.
- BigInt JSON Serialization: Added recursive conversion for Soroban i128 values so that large balances serialize safely without JSON crashes.
- Process Lifecycle: Added environment variable validation and graceful shutdown for SIGTERM and SIGINT.

Frontend DApp (Commit c50f018, frontend/src/App.jsx and frontend/src/index.css):
- Freighter Integration: Upgraded @stellar/freighter-api integration with extension detection, public key request, and active network verification. Displays a warning if wallet is on Mainnet instead of Testnet.
- Transaction Simulation and Assembly: Implemented rpc.assembleTransaction footprint preparation before requesting user signatures, avoiding uncalculated gas failures.
- Transaction Tracking: Real-time ledger polling with transaction status cards and direct links to stellar.expert Testnet explorer.
- Remittance Progress: Dynamic percentage progress bar and quick-fill contribution buttons (25%, 50%, 100% remaining).
- Design System: Custom CSS dark-mode glassmorphic theme with Inter and Outfit typography, responsive layouts, and accessible markup.

5. STELLAR ECOSYSTEM RELEVANCE

Stellar Split addresses cross-border remittance friction in emerging markets, where traditional money transfer operators charge 6% to 8% on small-ticket transfers ($20 to $100). Shared family obligations (medical emergencies, education, utility bills) require multi-party coordination abroad.

By leveraging Stellar low-fee settlement and Soroban smart contracts:
- Expense targets are cryptographically transparent.
- Fractional contributions are escrowed under contract custody.
- Payers retain self-custody and cannot overpay past the remaining balance.
- Beneficiaries receive atomic payouts upon completion.
- The protocol interfaces directly with Stellar Asset Contracts (SAC), preparing it for fiat-backed stablecoins such as USDC and EURC.
